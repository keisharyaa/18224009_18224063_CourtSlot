# Checklist deployment STB — belum dijalankan

Asisten STB perlu memastikan arsitektur CPU, RAM, Docker/Compose, port host yang tersedia, gateway aaPanel yang sudah ada, routing tunnel, domain yang benar, dan izin akses. `courtslot.stei.fun` masih target kontrak, belum diverifikasi. Contoh Nginx di `deploy/nginx/courtslot.conf.example` hanya template loopback; jangan memasangnya pada port 80 tanpa pemetaan gateway yang disepakati.

1. Salin source yang sudah direview ke STB. Buat `.env` lokal dari `.env.example`, isi key AERIVA dan LocalLoop yang berbeda serta token secret acak minimal 32 karakter melalui kanal privat. Jangan commit `.env`.
2. Pilih `COURTSLOT_BIND_PORT` yang kosong di host; default 8000 hanya mengikat `127.0.0.1`. Periksa konflik port dan sesuaikan upstream gateway. Tidak ada token tunnel atau kredensial STB di Compose.
3. Jalankan `docker compose config`, `docker compose build`, `docker compose up -d`, lalu `docker compose exec -T api python -m app.seed`. Lihat `docker compose ps` dan `docker compose logs --tail=100 api`.
4. Di STB, uji `curl -i http://127.0.0.1:<port>/api/health` dan `curl -i http://127.0.0.1:<port>/docs`. Dengan key privat: `curl -i -H 'X-API-Key: <key>' 'http://127.0.0.1:<port>/api/public/facilities'`, detail `/api/public/facilities/fac-bandung-lapangan`, serta availability dengan `start`/`end` berzona dan URL encoded.
5. Setelah gateway/tunnel dikonfigurasi asisten, ulangi smoke test melalui hostname HTTPS dari jaringan luar, cek sertifikat, OpenAPI, key salah 401, dan bahwa respons tidak memuat identitas warga. Barulah perbarui API Registry.
6. Uji persistence: catat jumlah fasilitas/reservasi, jalankan `docker compose up --build --force-recreate -d` tanpa `down -v`, lalu bandingkan data. Jangan menjalankan `docker compose down -v` karena menghapus volume.

Rollback aplikasi: lihat nama image aktual dengan `docker compose images` karena nama mengikuti direktori proyek. Sebelum build baru, jalankan `docker image tag <IMAGE_AKTUAL>:latest <IMAGE_AKTUAL>:rollback`. Jika image baru perlu dibatalkan, jalankan `docker image tag <IMAGE_AKTUAL>:rollback <IMAGE_AKTUAL>:latest` lalu `docker compose up -d --no-build --force-recreate`; jangan jalankan `down -v`. Pastikan image lama kompatibel dengan skema database yang sudah termigrasi; versi aplikasi tahap 2 tidak dapat membuka skema v2. Migrasi v2 menambah tabel dan tidak mempunyai rollback skema otomatis. Ambil backup SQLite yang konsisten sebelum upgrade produksi, lalu pulihkan hanya dengan persetujuan pemilik data bila rollback data diperlukan.
